## local

参照実装です。他のバックエンドを書くときの手本になります。

- 書き込みは一時ファイル + `Chtimes` + `os.Rename`
- `Features.OSPath` が真。ドライブレターや UNC はそのまま扱う
- Dropbox 独自ハッシュも計算できるので、`local ↔ dropbox` で `--checksum` が使える

## dropbox

### 内容の切り詰めを根治した

以前は全経路が 150MiB の `io.LimitReader` を通っており、サイズが過小に
伝わると先頭だけ送られて**成功扱い**になっていました。

いまは宣言サイズを信用しません。先を読んでみて収まりきるなら1回の要求で
送り、超えるならアップロードセッションに切り替えます。

```go
head, atEOF, err := readHead(r, smallUploadLimit)
```

`limit + 1` バイト読んで判断します。`limit` ぴったりのファイルを
「まだ続きがある」と誤らないためです。

1回で送る場合は content hash を添えるので、通信の途中で内容が欠けたら
サーバー側で弾かれます。

### エラーの取り出し

SDK は経路ごとに別のエラー型を生成します（`GetMetadataAPIError` など）。
どれも `dropbox.APIError` を**埋め込んで**いますが、埋め込みは別の型なので
`errors.As` では取り出せません。リフレクションで埋め込みを直接見ています。

これに気づかず実装したときは、失敗の分類が全滅していました。
適合性スイートが「Remove が not_folder で落ちる」と教えてくれました。

## googledrive

### パスの解決

Drive はパスの木ではなく**IDの網**です。`/a/b/c.txt` のような指定が
API にないので、根から1段ずつ名前で引き当てます。

以前の実装には2つの問題がありました。

- 1段ごとにフォルダの中身を全件列挙していた（件数の多いフォルダで大量のやりとり）
- 途中の段が見つからないとき**黙って読み飛ばし、ひとつ上の階層の中身を返していた**

後者は、存在しない場所を指定したのにエラーにならず、別のディレクトリを
対象にコピーや削除をしてしまう、という性質のものです。

いまは名前で絞り込んだ問い合わせを1段につき1回行い、見つからなければ
その場で失敗させます。解決したIDは覚えるので、同じ木を歩くあいだは
問い合わせが増えません。

### 一覧の続き

以前は `nextPageToken` を `Fields` に指定しながら**たどっていません**でした。
子が1000件を超えるフォルダで、超過分がエラーも警告もなく欠落していました。

### 独自形式

Google ドキュメントなどは実体を持たず、サイズも持ちません。
`SizeUnknown` として扱い、読もうとしたらはっきり失敗させます。
`native_files: skip` で一覧から外せます。

### 削除

既定でゴミ箱に入れます。以前は完全削除でした。

## onedrive

### 公式 SDK を使わない

`msgraph-sdk-go` は生成部品が巨大で、取り込むだけでビルドと試験の時間が
桁違いに伸びます。hbg が触るのは10ほどの窓口なので割に合いません。

### 更新時刻

`lastModifiedDateTime` は「サーバー上で変わった時刻」で、元のファイルの
更新時刻ではありません。同期の判断に要るのは
`fileSystemInfo.lastModifiedDateTime` のほうです。

### 分割送信

- 1つぶんは **320KiB の倍数**でなければ受け付けられない
- 順番どおりに送る必要がある
- 全体の大きさは最後を送る時点で分かればよい

次のひとかたまりを先に読んでから送る形にしたので、事前にサイズが
分からなくても送れます。読めた量が足りなければ、そこが最後だと分かります。

送り先は署名済みの一時的な接続先で、**認証の情報を付けると拒否される**
ことがあります。送る直前に取り除いています。

### ハッシュを入れていない

OneDrive が返すのは `quickXorHash` です。これを hbg 側で計算できないと
`--checksum` が成り立ちません。実装自体は難しくないのですが、公式の
照合用の値と突き合わせて確かめる手立てがありません。

間違ったまま入れると「検証したつもりで検証されていない」という、
いちばん避けたい状態を作ります。できないと申告しています。

## s3

### ディレクトリの見せかけ

オブジェクトストレージにディレクトリはありません。区切り文字を指定して
問い合わせると、同じ接頭辞を持つものがひとまとめにされて返るので、
それをディレクトリとして扱います。

空のディレクトリは、末尾が `/` の空のオブジェクトで表します（rclone と同じ）。

### 更新時刻

オブジェクトストレージが持つのは「書き込まれた時刻」です。そのまま比較に
使うと、取り出す向きの同期で毎回コピーし直すことになります。

元の時刻を `x-amz-meta-mtime` に入れ、そちらを使います。書式は rclone に
合わせてあるので、同じ入れ物を両方の道具から使えます。

一覧の応答にはこの項目が含まれないので、既定では1件ずつ問い合わせて
補います（`list_metadata: head`）。

### 非 AWS 提供元での署名

`aws-sdk-go-v2` は2025年1月の版から、要求に CRC32 の検査値を既定で
付けるようになりました。R2 や B2 ではこれが署名の食い違いとして
拒否されます。AWS 以外では、相手が求めたときだけ付けます。

### ハッシュ

分割送信の ETag は中身の MD5 になりません。転送元で MD5 が分かっていれば
`x-amz-meta-md5chksum` に控えます。控えのないものは、黙って ETag を
MD5 として扱いません（常に食い違うことになるため）。

## sftp

- 書き込みは `.hbgpart` + `posix-rename@openssh.com`
- ホスト鍵は `$HOME/hbg/configs/known_hosts`。`~/.ssh` を書き換えない
- `accept-new` でも、**記録済みの鍵が変わっていれば拒否**する
- 使えるホスト鍵の種類を記録から決める。指定しないと、記録にあるのとは
  別の種類の鍵を提示されて「変わった」と誤判定される（有名な罠）

## smb

`\\計算機\共有` という書き方は受け付けません。Windows のパスの書き方と
ファイル名の区切りが混ざると、どこまでが計算機名でどこからが共有名なのか
決められません（`path.Clean` に通すと潰れます）。`host` と `share` に
分けて書いてもらいます。

依存は `cloudsoda/go-smb2` です。`hirochachacha/go-smb2` は2022年で
止まっており、cloudsoda はそのフォークで rclone も移っています。

## webdav

### ライブラリを使っていない

`studio-b12/gowebdav` を使おうとしましたが、書き込みの作りに2つ問題が
ありました。

- 内容をいったんすべてメモリに載せてから送る（読み手が `io.Seeker` でない場合）
- ファイルを1つ書くたびに親へ MKCOL を投げる。要求が倍になるうえ、
  同じディレクトリへ並行して書くとロックがぶつかって 423 で断られる

どちらも外から直せなかったので、使う7つの手続き
（PROPFIND / GET / PUT / MKCOL / DELETE / MOVE / COPY）を自前で組み立てました。

### 更新時刻

`{DAV:}getlastmodified` はサーバーが管理する項目なので、PROPPATCH では
変えられません。Nextcloud と ownCloud だけが `X-OC-Mtime` を受け付けます。

`preset: generic` では「保持できない」と申告します。

### 転送先を追わない

書き込みや問い合わせでは転送（リダイレクト）を追いません。PUT が転送されると、
送り直しのときに GET になってしまうことがあり、中身が消えかねません。

## ftp

旧実装（git 履歴の `hbg.go`）には3つ問題がありました。

- ログインの結果を確かめていなかった
- 更新時刻をまったく扱っていなかった（ヘルプに「タイムスタンプは消滅します」と書かれていた）
- 暗号化していなかった

いまは `MFMT` に応じる相手なら時刻を保持し、既定で `AUTH TLS` を試みます。

FTP は1つの接続で1つのやりとりしかできないので、接続をまとめて持ちます。
途中でやめたときや 421 が返ったときは、その接続を**捨てます**。
状態の分からない接続を戻すと、次に借りた側まで巻き添えになります。

## 共通の仕掛け

### `internal/dircache`

WebDAV・OneDrive・FTP はどれも、親ディレクトリがない場所への書き込みを
断ります。断られてから作ってやり直す順にはできません（本文の送信が
始まっていることがあり、読み手を巻き戻せない）。

一度作った（あるいはあると分かった）ディレクトリを覚えておきます。
転送の側が先に `Mkdir` を呼ぶので、ふだんは書き込みのときに要求が
増えません。
